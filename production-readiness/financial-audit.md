## 1. Micro-Unit Currency Representation

To permanently prevent floating-point IEEE-754 roundoff errors (e.g. `0.1 + 0.2 = 0.30000000000000004`), the platform uses integer-based micro-units:

$$\text{Micro-Units} = \text{Decimal Amount} \times 1,000,000$$

- **1.00 USD** = `1,000,000 µu`
- **$0.004500 (Provider Cost)** = `4,500 µu`
- **$0.009500 (Client Charge)** = `9,500 µu`
- **$0.000250 (Agent Commission)** = `250 µu`
- **$0.004750 (Platform Profit)** = `4,750 µu`

All database schema columns for balances, rates, charges, and ledger amounts use PostgreSQL `BIGINT` mapped to JavaScript `BigInt`.

## 4. Transaction Atomicity & Concurrency Controls

- All balance mutations occur within Prisma interactive transactions (`prisma.$transaction(async (tx) => { ... })`).
- Whenever a message is billed, the client debit, agent commission credit, platform treasury credit, and ledger entries are committed in a single atomic database transaction.
- If any sub-operation fails, the entire transaction rolls back, guaranteeing zero partial writes or lost revenue.
